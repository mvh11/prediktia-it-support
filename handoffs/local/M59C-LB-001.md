## QUERY PLAN (exacto)

Ejecutar una sola vez, sobre la base del `.env`:

```bash
mkdir -p ~/prediktia-audit-local          # fuera de cualquier repo
# DIRECT: añadir defensa extra a nivel de sesión
PGOPTIONS='-c default_transaction_read_only=on' \
psql "$PREDIKTIA_AUDIT_DSN" -X -v ON_ERROR_STOP=1 \
  -f <it-repo>/scripts/read-only/neon_privilege_audit.sql \
  > ~/prediktia-audit-local/M59C-LB-001-raw.txt 2>&1
# POOLER: el pooler de Neon no acepta PGOPTIONS; ejecutar igual pero sin
# PGOPTIONS. La guardia principal es BEGIN TRANSACTION READ ONLY ... ROLLBACK
# dentro del script.
```

Secciones del script → requisito cubierto:

| Sección | Cubre |
|---------|-------|
| 00 SESSION | base exacta, `current_user`, UTC, `tx_read_only` |
| 01 / 01b | versión PostgreSQL, extensiones |
| 02 DATABASES | bases visibles, owners, ACL de base |
| 03 / 03b ROLES | roles y atributos (sin contraseñas), membresías directas |
| 09 / 09b | rutas de privilegio efectivas, roles amplios (`pg_read_all_data`, `pg_write_all_data`, `neon_superuser`…) |
| 04 DATABASE PRIVILEGES | CONNECT / CREATE / TEMP, incluido PUBLIC |
| 10 PUBLIC TEMP | `public_has_temp`, `public_has_connect`, `public_has_create` |
| 05 SCHEMAS | owners, USAGE/CREATE, PUBLIC |
| 06 / 06b / 06c | inventario de objetos, owners, ACL por objeto y columna |
| 06d / 06e | vistas (bypass de RLS por owner), funciones SECURITY DEFINER |
| 07 RLS POLICIES | políticas, comandos, roles (más `rls_enabled`/`rls_forced` en 06) |
| 08 DEFAULT PRIVILEGES | `ALTER DEFAULT PRIVILEGES` vigentes |
| 11 SETTINGS | `default_transaction_read_only`, `row_security`, etc. |

Verificaciones tras ejecutar:
- código de salida 0, sin líneas `ERROR`/`FATAL`;
- sección 00 con `tx_read_only = on`;
- termina en `=== END (ROLLBACK ejecutado; ningún cambio) ===`.

Si la salida muestra otras bases PREDIKTIA en la sección 02: **registrarlas**,
no conectarse a ellas (requieren otro paquete).

Al terminar: `unset PREDIKTIA_AUDIT_DSN` (bash) o
`Remove-Item Env:PREDIKTIA_AUDIT_DSN` (PowerShell).
